\section{Overview}
PALM-mbQTL is software for microbiome–host genetics association studies. 
It implements the recently developed PALM method (Genome Biology, to appear). 
The software includes two variants of PALM: PALM1 and PALM2. 
Both methods are run in two steps: 
Step 1 fits a null model (microbiome ~ covariates) that does not use genotype data; 
Step 2 uses the Step 1 outputs together with SNP genotype files to compute association 
summary statistics (effect estimates and standard errors). 
Please run both PALM1 and PALM2 for each study cohort and return the resulting 
summary statistics.

\section{Installation (Apptainer)}

PALM-mbQTL is designed to run inside an Apptainer (Singularity-compatible)
container on Linux-based systems, including high-performance computing (HPC)
clusters.
All workflow steps are executed through shell scripts that invoke Apptainer
internally.

\subsection{Apptainer}

Apptainer must be available on the system.

\subsection{Container image}

The Apptainer container image \texttt{palmmbqtl.sif} is provided together with
the project and is already located under the project root directory
(\texttt{WORK/}).
No additional download or build step is required.

\subsection{Project setup}

Unpack or clone the PALM-mbQTL project directory to a working location.
After entering the project root directory, users may define the working
directory via a local environment file.
Specifically, create or edit a \texttt{.env} file to store the absolute path
of the current project directory:

\begin{verbatim}
cd /path/to/PALMmbQTL
nano .env
\end{verbatim}

with the following content:

\begin{verbatim}
export WORK=$(pwd)
\end{verbatim}

Load the environment variables into the current shell session:

\begin{verbatim}
source .env
\end{verbatim}

\subsection{Test run}

Before deploying the workflow on large-scale data or submitting jobs to an
HPC scheduler, it is recommended to first perform a test run using the
example data.

Execute the core workflow steps sequentially:

\begin{verbatim}
bash workflow/info.sbatch
bash workflow/step1.sbatch
bash workflow/step2.sbatch
\end{verbatim}

This test run verifies that the configuration, input files, and container
environment are correctly set up and that the pipeline produces the expected
outputs under \texttt{example/output/}.




\section{Example input files}

The example input data live in \texttt{example/input/}:

\begin{itemize}[nosep]
  \item \texttt{abd.txt}: abundance file.
  \item \texttt{cov.txt}: covariate file.
  \item \texttt{geno.bed}, \texttt{geno.bim}, \texttt{geno.fam}:
        PLINK genotype files.
  \item \texttt{grm.rds} (optional): precomputed GRM RDS file. 
        Required only when analyzing family-based data.
\end{itemize}

\subsection{\texttt{abd.txt}}
\begin{verbatim}
IID	g1	g2	g3
DKR276	3789	674	728
DLB658	3404	1670	194
NTY571	1399	1269	184
\end{verbatim}
(IID is shortened here) \\
Requirements:

\begin{itemize}[nosep]
  \item Tab-delimited.
  \item One row per sample.
  \item First column: unique sample ID (name can be anything; in the example it is `IID`).
  \item Remaining columns: non-negative integer counts for microbial features. 
  No NAs.
  The sum of counts per sample is used as sequencing depth by default. 
  Therefore it must be positive for all samples.
\end{itemize}

\subsection{\texttt{cov.txt}}
\begin{verbatim}
IID	AGE	SEX	PC01	PC02	PC03	PC04	PC05
DKR276	1.82742057825961	1	0.010171	-0.00258488	-0.00222028	-0.00296875	0.00288836
DLB658	-0.305812631038716	0	-0.00853818	-0.00585994	-0.000248601	-0.0078163	0.00122123
NTY571	1.24733084590656	1	-0.00688391	-0.00522521	0.00244565	-0.00342203	0.00128414
\end{verbatim}

Requirements:

\begin{itemize}[nosep]
  \item Tab-delimited.
  \item One row per sample.
  \item First column: unique sample ID (name can be anything; in the example it is `IID`). 
  Sample ID column must match the `IID` column in `abd.txt`.
  \item Remaining columns: covariates that will be adjusted for in the model.
\end{itemize}

\subsection{\texttt{geno.bed/.bim/.fam}}

Standard PLINK binary format:

\begin{itemize}[nosep]
  \item \texttt{geno.bed}: genotype matrix.
  \item \texttt{geno.bim}: SNP annotations (chromosome, SNP ID,
        position, alleles).
  \item \texttt{geno.fam}: sample information; IDs must match the
        microbiome/covariate files.
\end{itemize}

\subsection{grm.rds}
\begin{figure}[htbp]
  \centering
  \includegraphics[width=1\textwidth]{figures/grm.png}
\end{figure}
Requirements:
After reading the GRM file using \texttt{readRDS()} in R, the returned object 
should be a list with two elements:
\begin{itemize}
  \item \texttt{K}: a numeric matrix of dimension $N \times N$, representing the genetic relationship matrix
  \item \texttt{sample.id}: a character vector of length $N$, indicating the sample order corresponding to \texttt{K}
\end{itemize}

The row and column order of \texttt{K} must exactly match the order of \texttt{sample.id}.

\subsection{Notes}  
Sample IDs across different input files (e.g., \texttt{abd.txt}, \texttt{cov.txt}, genotype files, and \texttt{grm.rds}) do not need to appear in the same order. The pipeline will internally align samples by their IDs.

However, the set of sample IDs must be identical across all input files. Samples present in one file but missing in another are not allowed.


\section{Example output files}

The test run will produce two sets of outputs under \texttt{example/output/}:

\begin{itemize}[nosep]
  \item Files prefixed with \texttt{palm1} correspond to the output from 
  using the main PALM method (PALM1), for
    example \texttt{palm1\_step1\_allpheno.rda} and
  	\texttt{palm1\_step2\_chr1\_g1.txt}.
  \item Files prefixed with \texttt{palm2} correspond to the
    output from using a variant of PALM method (PALM2), 
    for example \texttt{palm2\_step1\_allpheno.rda}
    and \texttt{palm2\_step2\_chr1\_g1.txt}.
  \item Filenames: \texttt{chr1} (chromosome name), \texttt{g1} (phenotype/gene name).
\end{itemize}

Example output snippets:

\section{Configuration file: \texttt{config.sh}}

The file \texttt{config.sh} is the main user-facing configuration file of \texttt{PALM-mbQTL}.
All analysis parameters, input paths, and output prefixes are defined in this file.
Users only need to modify \texttt{config.sh}; no changes to the workflow scripts are required.

\subsection*{Required parameters}

\begin{itemize}
  \item \texttt{PALMmethod} \\
  Integer indicating which PALM method to run:
  \begin{itemize}
    \item \texttt{1}: Main PALM method
    \item \texttt{2}: A variant of the PALM method
  \end{itemize}

  \item \texttt{inputFolder} \\
  Directory containing all input files. Should be put under \texttt{WORK/}.

  \item \texttt{outputFolder} \\
  Directory for all outputs. It will be created automatically if it does not exist. 
  Will be generated under \texttt{WORK/}.

  \item \texttt{genoFile} \\
  Path prefix to PLINK genotype files. If the file extension is omitted, the script expects
  \texttt{.bed}, \texttt{.bim}, and \texttt{.fam} files with the same prefix.
  Currently, only PLINK format is supported. Should be put under \texttt{inputFolder/}.

  \item \texttt{abdFile} \\
  Path to abundance file. Should be put under \texttt{inputFolder/}.

  \item \texttt{covFile} \\
  Path to covariate file. Should be put under \texttt{inputFolder/}.

  \item \texttt{grmFile} \\
  Path to the GRM (genetic relationship matrix) RDS file.
  This parameter is \textbf{required only when analyzing family-based data}, 
  where genetic relatedness among samples must be explicitly modeled. 
  In such cases, users must provide a precomputed GRM file.
  For population-based studies with unrelated samples, users can set 
  \texttt{grmFile = NULL}, and an identity matrix will be used when fitting 
  the null model.
  The GRM file should be placed under \texttt{inputFolder/} and must be an 
  RDS file containing:
  \begin{itemize}
    \item \texttt{sample.id}: a character vector of sample IDs
    \item \texttt{K}: an $N \times N$ symmetric GRM matrix ordered exactly 
    as \texttt{sample.id}
  \end{itemize}
  If \texttt{grmFile} is set to \texttt{NULL}, no GRM RDS file is needed.

\end{itemize}

\subsection*{Chromosome control}

\begin{itemize}
  \item \texttt{chrom} \\
  Chromosome to analyze in step 2.  
  Set to a specific chromosome number (1-22) to analyze one chromosome at a time.
  Set to \texttt{NULL} to analyze all chromosomes.
  This parameter can also be used for parallel execution, for example by
  setting \texttt{chrom=\$\{SLURM\_ARRAY\_TASK\_ID:-NULL\}} in a SLURM array job.
\end{itemize}

\subsection*{Optional parameters}

The following parameters are pre-defined in \texttt{config.sh} and usually do not need to be modified.

\begin{itemize}
  \item \texttt{SIF} \\
  Path to the Apptainer/Singularity image file (\texttt{.sif}).

  \item \texttt{outputSnpFile} \\
  Output file containing SNP information.

  \item \texttt{outputFeatureFile} \\
  Output file containing feature information, including average proportion and prevalence.

  \item \texttt{outputSeqDepthFile} \\
  Output file containing sequencing depth information.

  \item \texttt{palm1\_step1\_prefix} \\
  Output prefix for step 1 when \texttt{PALMmethod=1}.
  The fitted null model is saved as \texttt{\$\{palm1\_step1\_prefix\}.rda}.

  \item \texttt{palm2\_step1\_prefix} \\
  Output prefix for step 1 when \texttt{PALMmethod=2}.
  The fitted null model is saved as \texttt{\$\{palm2\_step1\_prefix\}.rda}.

  \item \texttt{palm1\_step2\_prefix}, \texttt{palm2\_step2\_prefix} \\
  Output prefixes for step 2 results.  
  If \texttt{chrom=NULL}, results from all chromosomes are merged automatically;
  otherwise chromosome-specific output files are generated.
  We suggest running jobs in parallel across chromosomes.
\end{itemize}

\subsection*{Notes}
\begin{itemize}
  \item All parameters defined in \texttt{config.sh} are exported as environment variables
and shared across all workflow scripts.
Users should \textbf{not} modify the workflow scripts directly.
  \item Except for \texttt{WORK}, all paths specified in \texttt{config.sh} are
interpreted as relative paths.
Input files (e.g. \texttt{genoFile}, \texttt{abdFile}, \texttt{covFile})
are specified relative to \texttt{inputFolder}, while output files and
prefixes are specified relative to \texttt{outputFolder}.
In practice, users only need to provide file names or prefixes, and place
the corresponding files in the appropriate directories.
\end{itemize}



\section{Workflow steps}

From a user perspective, running PALM-mbQTL consists of four simple steps.
Users do not need to interact with individual R scripts directly.

\begin{enumerate}
  \item \textbf{Prepare input data following the example}

  Prepare your own input data by following the structure of the provided
  \texttt{example/} directory.
  This includes the abundance file (\texttt{abd.txt}),
  the covariate file (\texttt{cov.txt}),
  the PLINK genotype files (\texttt{.bed/.bim/.fam}),
  and optionally the GRM RDS file (\texttt{grm.rds}).
  File formats and requirements are described in Section~2.

  \item \textbf{Edit the configuration file \texttt{config.sh}}

  Open \texttt{config.sh} and modify the parameters.
  In particular, set \texttt{PALMmethod}, \texttt{inputFolder},
  \texttt{outputFolder}, \texttt{genoFile}, \texttt{abdFile}, \texttt{covFile},
   \texttt{grmFile} (if applicable), and \texttt{chrom}.
  All analysis parameters are defined in this file.

  \item \textbf{Run the workflow scripts}

  The workflow is executed via a set of shell scripts located under
  \texttt{workflow/}.  
  Each script reads parameters from \texttt{config.sh} and performs a
  well-defined analysis task.
  The scripts can be executed directly using \texttt{bash} on a local machine
  or submitted to a job scheduler (e.g. \texttt{sbatch}) on HPC systems.
  \noindent\textbf{Note:}  
  The \texttt{\#SBATCH} directives at the beginning of each \texttt{.sbatch} 
  script (e.g., job name, partition, CPU, memory, time limits and log info) 
  are provided as examples and can be modified by users to match their own 
  HPC environment and resource requirements.


  \begin{itemize}
    \item \texttt{info.sbatch} \\
    Generates basic summary information for quality control and reporting,
    such as:
    SNP-level information from the genotype files,
    feature-level and sequencing depth information from the abundance file.
    This step does not perform association testing and is typically run once
    per study.

    \item \texttt{step1.sbatch} \\
    Fits the null models for all microbiome features.
    Input files are first validated for consistency.
    The fitted null models are saved and will be used by step 2.

    \item \texttt{step2.sbatch} \\
    Performs single-variant association testing using the fitted null models 
    and SNP genotypes.
    This step supports chromosome-wise execution via the \texttt{chrom} parameter
    in \texttt{config.sh}.
    We encourage users to run step 2 separately for different chromosomes 
    (e.g. \texttt{chrom=1},
    \texttt{chrom=2}, \ldots), enabling straightforward parallelization on
    high-performance computing systems.
  \end{itemize}


  \item \textbf{Inspect and analyze the results}

  Output files are written to \texttt{outputFolder}.
  Association results are generated per chromosome and per phenotype, while
  summary files provide feature, SNP, and sequencing depth information.
  Users can proceed with downstream analysis, visualization, and interpretation
  based on these outputs.
\end{enumerate}
